# youwang · 论文精读技能

这里维护可在多台电脑上安装、持续合并阅读反馈的 Codex 技能。当前核心技能是 [payment-channel-paper-reader](skills/payment-channel-paper-reader/SKILL.md)，用于区块链支付通道、状态通道和支付通道网络论文。

最新版本以 [SKILL.md 的 metadata.version](skills/payment-channel-paper-reader/SKILL.md) 为准；具体修改可查看仓库提交记录。

## 怎样读一篇论文

精读以论文实际章节为主线，默认中文讲解，保留英文术语、算法原名和数学符号。可以阅读全文，也可以只追踪一个算法、局部交互或失败路径。

| 内容 | 默认处理方式 |
|---|---|
| 摘要 | 完整翻译，保留条件、结果与限定语 |
| 所有纳入范围的正文 | 保留到最深的小节与段首编号项，逐段译读并从原文反查译文落点。难点、公式、算法和图表就近讲解 |
| 引言与背景 | 用同一场景走一遍原有办法，指出哪个条件改变、谁在哪一步受限、本文怎样处理。拓扑、费用、可见性或状态的对照紧邻对应段落 |
| 模型与预备知识 | 说明角色、通道、假设、符号与输入来源，补足理解当前构造所需的基础 |
| 方法与算法 | 每章前列本章参数、公式与接口，随文区分已有工具、直接算法、新构造和交互伪代码。关键验证展开代入、条件与结果 |
| 支付过程 | 正文放本章的原图、局部计算及交互。配套《前因后果》沿作者原例或明示的教学例，从建立或入金，逐步走到更新、验收与结算 |
| 安全内容 | 还原对手、假设和主张，按触发分段讲理想功能，形式化证明依阅读范围展开，完整解释实际支付中的验签、证明、共识及授权 |
| 性能／实验 | 完整翻译实验文字与图表说明，嵌入原图原表，用一两句话读出条件与结果 |
| 结论与反思 | 区分原文结论和扩展思考，讨论具体机制、设计取舍及可借鉴的研究问题 |

正文保留原章节、算法名及节、式、图表的交叉引用。专业名词首次给英文原名和职责，译名不统一时保留英文。在独立的《前因后果》中用同一实例画出必要的准备、支付和结算；关键验证写清由谁执行、核对什么、通过后哪份状态生效，以及原文规定的失败去向。

### 两份成稿和一份本机索引

[打开按任务编排的详细提示词](skills/payment-channel-paper-reader/references/authoring-prompts.md)

- `<论文>_全文精读.md` 保留完整摘要、引言、原章节译文、就地解释、章内公式、原图和局部算法。结论先译再总结，随后列跨论文思考与按类型整理的参考文献。两份精读文档都只在参考文献部分显示文献编号。
- `<论文>_前因后果.md` 从链上扩展需求引到本文的通道类型、相关工作、问题与贡献，另设「完整交易交互」，用同一实例逐步展开准备、各笔付款、核验和结算。每个阶段在图中或紧邻图的文字里写明收发、参数和状态或资金结果。链、结算资产和测试环境分别核对。详见[配套稿提示词](skills/payment-channel-paper-reader/references/causal-narrative.md)。
- 两份链接交付后，在本机技能的 `library/已读论文.md` 按论文增补总结、研究想法和一至两张代表原图。重读更新原条目。个人库只留本机，公开仓库提供[归档规范](skills/payment-channel-paper-reader/references/reading-library.md)。

## 讲解深度持续保留，呈现随论文调整

完整算法、参数来源、逐步推导、真实消息与接收检查、状态／资金／秘密变化、阶段出口和图文解释是稳定要求。读者应能沿同一笔付款重放协议；转抄公式、罗列接口或只给总览不能代替精读。正常显示公式而不附源码，不减少这些内容。

章节内组织、行组、示例人数、图的布局和必要分图数量按实际论文调整；不照搬一篇的角色、阶段或编号。减少重复工具操作，不减少已授权的解释深度；总览之后按需给足关键阶段的详图与连续说明。

## 公式：直接正常展示

精读中直接显示公式和算法。算法定义先展示已知调用式，紧接完整说明。多步算法在框内标步骤号，保留原有行号，长式按语义续行。协议和通道过程沿图讲解。单独的 WPS 公式转写适用转写格式选择。

先核对原文及必要的显示效果；普通公式显示正常时，不额外安装渲染依赖、搭建测试网页或批量截图。出现乱码、溢出或实际渲染错误时再定向检查。

## 图：按实际交互选，不固定一种模板

作者原图按原色直接内嵌。背景图与交易总览沿本篇图例重绘。原图用人物和合约图标时沿用其造型，用节点和通道边界时沿用其分组与线型。正文配局部交互图。配套稿可用原图分面、两方或三方传参、两段枢纽交互、逐跳网络图或实体动作框串起执行。

配套稿用一张足宽主图或衔接的分面走通一笔具体付款。可以重排原图的节点，在同一幅内分阶段放大关键交互，保留本篇的角色、邻接关系和通道边界。逐跳标出必要载荷、实际转发者和状态变化；请求与回复分别标方向和字段。优先展开作者原例，教学取值在图旁说明。没有模型图时依据正文定义画出关系。详见[端到端支付交互总图](skills/payment-channel-paper-reader/references/protocol-flow-diagrams.md#端到端支付交互总图)。

- **参与方交互图**：本地计算、参数和结果对齐执行方，消息两端对齐实际收发方。多人共同操作标明涉及的角色。
- **紧凑协议框**：双栏或多栏伪代码配合消息箭头，适合注册、签名交换、谜题承诺等局部协议。
- **阶段与分支总览**：把公共阶段、不同支付情况和状态衔接组合展示，必要时嵌入局部交互。
- **结构、交易或状态图**：按真实通道关系、花费依赖与状态转移选择，不把所有箭头都理解为消息时序。

仅在确实拥挤、标签重叠或端点含混时调整走线、分区、拆图，或采用不丢失信息的广播摘要；不把所有交互都改成文本卡片。图的角色、字段、并发与失败条件来自论文，不能照搬样图的机制。

生成图中的参与方、消息字段、函数调用与公式统一采用正式论文数学排版，保留原文上下标、帽号、横线、波浪号及字体含义，不用普通文本或 Unicode 字符拼凑。说明文字、数学字体、线宽与留白保持一致；详见 [图内数学排版](skills/payment-channel-paper-reader/references/protocol-flow-diagrams.md#图内数学排版)。

修订时先核对并迁移适合正文的旧参数图。完整实例可复用已能读懂的图，或对模型图补入具体成员、消息与状态；新图按最终栏宽检查小字、箭头及留白。详见 [流程分类与成图](skills/payment-channel-paper-reader/references/protocol-flow-diagrams.md)。

## 开始使用

提供论文 PDF、正文或链接后发送：

~~~text
请用 $payment-channel-paper-reader 精读这篇论文，按章节完整译读，交付《全文精读》和《前因后果》两个 Markdown。完整交易放在《前因后果》，交付后更新本机已读论文。
~~~

只想看局部时，可以直接限定范围。需要按原图带着例子讲，可以这样说。

~~~text
请用 $payment-channel-paper-reader，只讲这部分的交互。按本篇系统模型图的画法带我走一笔交易，标出谁把什么交给谁、余额或状态发生什么变化。沿用作者已有的例子，另用详图解释关键算法。
~~~

全文先在聊天中按章节展示图文讲解，核心图紧邻解释；完成后交付两份相互链接的本地 UTF-8 Markdown，不能只发链接和简短总结。局部请求只处理相关部分。图按需嵌入，不自动附 PDF、压缩包或多套源码。阅读笔记、论文图和个人材料不会因为允许同步技能规则就被公开上传。

## 安装到另一台电脑

在目标电脑的 Codex 中发送：

~~~text
请使用 $skill-installer 安装这个 skill：
https://github.com/youwang2004/youwang/tree/main/skills/payment-channel-paper-reader
保留全部参考文件，安装到当前设备的个人 skills 目录，并校验安装结果。
~~~

若技能尚未显示，重新打开对话后核对。已存在同名技能时按更新处理，先比较版本和本地差异，不能直接清空或把重复安装失败当作成功。

## 同步与持续优化

让当前设备先获取仓库累计改进：

~~~text
请从 https://github.com/youwang2004/youwang 的 main 分支同步
skills/payment-channel-paper-reader 到本机个人 skills 目录。
先比较版本和未同步的本地改动，必要时合并，保留全部参考文件。
校验后说明实际安装版本，再用新版精读论文。
~~~

只想纠正本篇内容，直接追问即可。需要把反馈长期保留时发送：

~~~text
请更新论文精读 skill。把本次确认的长期要求合并到 youwang2004/youwang 的 main 分支，
更新 skills/payment-channel-paper-reader，保留已有规则，并同步当前设备。
README 的说明或调用示例受影响时一并更新。请报告改动、版本、校验和 GitHub 同步结果。
~~~

更新以仓库最新版本为基础，合并有效本地差异。发布时检查 README，涉及使用说明或调用方式时一并更新。提交时避免覆盖其他对话的新改动，完成后分别核实 GitHub 与本机。各电脑仍需实际同步，正在进行的其他对话需重新加载新版，登录同一账号不代表自动安装或同步。

更多维护细节见 [跨设备使用](skills/payment-channel-paper-reader/references/distribution.md) 与 [反馈与优化](skills/payment-channel-paper-reader/references/evolution.md)。
