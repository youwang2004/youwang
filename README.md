# youwang · 论文精读技能

这里维护可在多台电脑上安装、持续合并阅读反馈的 Codex 技能。当前核心技能是 [payment-channel-paper-reader](skills/payment-channel-paper-reader/SKILL.md)，用于区块链支付通道、状态通道和支付通道网络论文。

最新版本以 [SKILL.md 的 metadata.version](skills/payment-channel-paper-reader/SKILL.md) 为准；具体修改可查看仓库提交记录。

## 怎样读一篇论文

精读以论文实际章节为主线，默认中文讲解，保留英文术语、算法原名和数学符号。可以阅读全文，也可以只追踪一个算法、局部交互或失败路径。

| 内容 | 默认处理方式 |
|---|---|
| 摘要 | 完整翻译，保留条件、结果与限定语 |
| 所有纳入范围的正文 | 按段落和条目完整翻译，保留限定语、参数、图表信息及注释，译文、结构整理与补充讲解分别呈现，全文统一领域术语 |
| 引言与背景 | 讲清实际需求、既有办法、剩余瓶颈及本文切入点，按需补简洁辅助图 |
| 模型与预备知识 | 说明角色、通道、假设、符号与输入来源，补足理解当前构造所需的基础 |
| 方法与算法 | 逐项说明每个算法完成什么任务，展开计算、检查、输出和下游用途 |
| 支付过程 | 原章节就地展示直接参数传递，全文最后用独立专章展开实际调用、推导、消息、检查与状态变化 |
| 安全内容 | 完整翻译已取得的形式模型与归约，另概述其证明目的和结论，完整解释实际支付中的验签、证明、共识及授权 |
| 性能／实验 | 完整翻译正文与图表文字，保留数据和条件，整理排版，不主动扩写分析 |
| 结论与反思 | 区分原文结论和扩展思考，讨论具体机制、设计取舍及可借鉴的研究问题 |

正文按原文章节与算法原名定位。原文页码与逐条来源留作核对，用户要求时提供。区分原文明确、据原文推导、材料缺失和教学示例；不编造缺失算法、恢复机制或实验结果。

## 讲解深度持续保留，呈现随论文调整

完整算法、参数来源、逐步推导、真实消息与接收检查、状态／资金／秘密变化、阶段出口和图文解释是稳定要求。读者应能沿同一笔付款重放协议；转抄公式、罗列接口或只给总览不能代替精读。正常显示公式而不附源码，不减少这些内容。

章节内组织、行组、示例人数、图的布局和必要分图数量按实际论文调整；不照搬一篇的角色、阶段或编号。减少重复工具操作，不减少已授权的解释深度；总览之后按需给足关键阶段的详图与连续说明。

## 公式：直接正常展示

精读中的公式、算法与推导直接正常显示，长式按语义换行，保留原文符号、参数、条件、分支和返回，不额外附加可复制源码，也不进行三种转写格式选择。每个算法用一个黑白框呈现，保留条件、分支和原有行号。原文只给接口时先框出调用式，再完整翻译正文描述，最后单列用途、输入、输出和可验证推导。

先核对原文及必要的显示效果；普通公式显示正常时，不额外安装渲染依赖、搭建测试网页或批量截图。出现乱码、溢出或实际渲染错误时再定向检查。

## 图：按实际交互选，不固定一种模板

新制图统一黑白。原章节用直接带参数的箭头就地呈现真实交互，篇末完整交易流程章用 LaTeX 或等效排版生成公式主导的多列协议图。后者在参与方列中写具体计算、推导和验收条件，重要检查和子程序可用细线框，详细中文解释置于图后。按协议内容和可读性在两类图中选取具体布局。

- **参与方交互图**：两方、三方、四方等都可以保留清楚的直接箭头，本地计算和接收检查放所属列。
- **紧凑协议框**：双栏或多栏伪代码配合消息箭头，适合注册、签名交换、谜题承诺等局部协议。
- **阶段与分支总览**：把公共阶段、不同支付情况和状态衔接组合展示，必要时嵌入局部交互。
- **结构、交易或状态图**：按真实通道关系、花费依赖与状态转移选择，不把所有箭头都理解为消息时序。

仅在确实拥挤、标签重叠或端点含混时调整走线、分区、拆图，或采用不丢失信息的广播摘要；不把所有交互都改成文本卡片。图的角色、字段、并发与失败条件来自论文，不能照搬样图的机制。

生成图中的参与方、消息字段、函数调用与公式统一采用正式论文数学排版，保留原文上下标、帽号、横线、波浪号及字体含义，不用普通文本或 Unicode 字符拼凑。说明文字、数学字体、线宽与留白保持一致；详见 [图内数学排版](skills/payment-channel-paper-reader/references/protocol-flow-diagrams.md#图内数学排版)。

多样性不意味着每次生成多套样图。按任务需要制作，复用正确且可读的图，定向修复有问题的部分；实际交付新图仍需渲染和目视核验。详见 [流程分类与成图](skills/payment-channel-paper-reader/references/protocol-flow-diagrams.md)。

## 开始使用

提供论文 PDF、正文或链接后发送：

~~~text
请用 $payment-channel-paper-reader 精读这篇论文。
按原文章节完整翻译并单列整理和讲解，统一术语，用黑白算法框和章内参数图呈现原文流程。
公式正常显示，图就近展示并逐图解释。把公式主导的完整交易流程分列图放在篇末，
交付整合 Markdown。
~~~

局部任务可以直接说“只讲这个算法如何接入支付流程”或“只重建超时退款的先后顺序”。无需每次重复全部规范。

全文先在聊天中按章节展示图文讲解，核心图紧邻解释；完成后再交付本地 UTF-8 Markdown 与文件链接，不能只发链接和简短总结。局部请求只处理相关部分。图按需嵌入，不自动附 PDF、压缩包或多套源码。阅读笔记、论文图和个人材料不会因为允许同步技能规则就被公开上传。

## 安装到另一台电脑

在目标电脑的 Codex 中发送：

~~~text
请使用 $skill-installer 安装这个 skill：
https://github.com/youwang2004/youwang/tree/main/skills/payment-channel-paper-reader
保留全部参考文件，安装到当前设备的个人 skills 目录，并校验安装结果。
~~~

若技能尚未显示，重新打开对话后核对。已存在同名技能时按更新处理，先比较版本和本地差异，不能直接清空或把重复安装失败当作成功。

## 同步与持续优化

让当前设备先获取仓库累计改进：

~~~text
请从 https://github.com/youwang2004/youwang 的 main 分支同步
skills/payment-channel-paper-reader 到本机个人 skills 目录。
先比较版本和未同步的本地改动，必要时合并，保留全部参考文件。
校验后说明实际安装版本，再用新版精读论文。
~~~

只想纠正本篇内容，直接追问即可。需要把反馈长期保留时发送：

~~~text
更新论文精读 skill：将本次对话中明确、需要长期保留的阅读要求，
合并到 https://github.com/youwang2004/youwang 的最新版
skills/payment-channel-paper-reader 中，并同步当前设备。
保留其他对话已加入的规则，报告改动、新版本及 GitHub 同步结果。
~~~

更新以仓库最新版本为基础，合并有效本地差异；提交时避免覆盖其他对话的新改动，完成后分别核实 GitHub 与本机。各电脑仍需实际同步，正在进行的其他对话需重新加载新版，登录同一账号不代表自动安装或同步。

更多维护细节见 [跨设备使用](skills/payment-channel-paper-reader/references/distribution.md) 与 [反馈与优化](skills/payment-channel-paper-reader/references/evolution.md)。
