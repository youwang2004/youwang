# 跨电脑安装与统一更新

用户的持久需求：在同一账号下的多台电脑上调用本技能，并让后续优化可以迁移到其他电脑。技能正文与参考文件只用相对路径，不依赖某台电脑的用户名、盘符、Python 或外部账户。

## 每台电脑首次安装

将包含完整 payment-channel-paper-reader 文件夹的安装包交给目标电脑的 Codex，可以直接说：

> 请将附件中的 payment-channel-paper-reader 安装到这台电脑的个人 skills 目录，保留全部参考文件，校验结构并检查能否被发现。若已有同名技能，先比较版本和本地修改，避免直接覆盖尚未合并的优化。

由目标环境依据自己的内置技能创建／安装说明确定个人目录；不要照抄另一台电脑的绝对路径，也不要只复制 SKILL.md 而漏掉 references 和 agents。安装后在下一次对话调用：

> 请用 $payment-channel-paper-reader 精读这篇论文，重建交互、算法改造及完整交易时序。

若选择器暂未显示技能，重新打开会话或重启 Codex 后核对。安装或保存成功不等于已经验证其他电脑；只报告实际检查过的设备和副本。

## 持续保持同一版本

使用用户明确指定的 Git 仓库（遵从其可见性选择）或已有的跨电脑同步文件夹作为唯一来源。尚未指定来源时，采用带版本号的完整安装包；不要创建一个虚构仓库地址或宣称账号已自动同步。

共享来源一旦配置，记录其实际地址、技能相对目录、分支（若有）和更新方式。源中只维护一份技能正文；各电脑更新它自己的安装副本。Git 仓库需要提交及推送，同步文件夹需要实际完成文件同步，其他设备仍需核对是否读取最新版本。没有建立更新机制时不能承诺自动更新。

更新过程：

1. 比较统一来源、当前安装副本的版本与内容。若多台电脑分别改动，即使版本号相同也要检查实际差异。
2. 在统一来源中合并已授权的反馈，保留不同设备上尚未合并的有效改动，运行技能结构校验。
3. 更新当前设备安装副本和版本包，并在具有访问能力时更新共享来源；用户没有给出共享来源前，不随意选择个人现有仓库或写入其他项目。
4. 报告新版本和实际同步状态；其他设备不可访问时明确仍待那些设备拉取／导入。不要只凭本机测试声称多设备已验证。

## 当前共享来源

统一来源：https://github.com/youwang2004/youwang

- 分支：main。
- 技能相对目录：skills/payment-channel-paper-reader。
- 当前版本以 SKILL.md 的 metadata.version 为准。
- 可见性：公开；用户已明确允许这个 skill 公开保存。
- 首次安装：目标电脑通过内置 skill-installer 或其支持的安装方式，从上述目录安装完整技能到个人目录。
- 后续更新：读取仓库新版本，与当前设备的本地改动比较，合并后更新该设备的个人目录；安装器拒绝已存在目录时不能把重复安装当作更新成功。
- 优化回写：用户要求可复用改进时，按 [反馈与优化](evolution.md) 先读取仓库最新版、合并反馈，再更新同一目录和版本，最后同步当前设备安装副本及可下载包。远端写入失败时保留本地修改并报告待推送，不能声称已经全设备生效。

这个地址用于共享版本，不自动建立账户级技能漫游，也不代表其他电脑已经完成安装或验证。

## 多个对话共用

每个新对话首次读论文时，用户可以说“先同步仓库最新版，再用这个 skill 精读”。同一对话内后续追问不必反复下载整份技能。若用户指出别的对话刚更新了规则，重新检查远端版本再继续。

在任意对话末尾，可用“更新论文精读 skill：把本次对话中需要长期保留的阅读要求合并到仓库最新版，并更新当前设备”汇总多条反馈。模型根据本次可见内容归纳，不能假装知道其他未读取对话的反馈；已写入仓库的规则从最新版继承。

新对话与其他电脑通过统一仓库获取这些规则。若旧对话仍在运行，明确让它重新同步后才可保证本次使用的是新版，不能宣称一次推送已替换所有正在进行的对话上下文。
