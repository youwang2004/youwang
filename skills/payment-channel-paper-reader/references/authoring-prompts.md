# 分任务精读提示词

全文任务按内容调用对应段落；单独读算法、图表或做汇报时可直接使用其中一段。方括号内填本篇实际对象。每段提示词都要求产出读者能直接读的图、公式或正文。

## 引言、摘要和配套讲稿

> 完整翻译摘要和引言，保留作者比较的对象、转折和限定语。先说清[实际用户]为什么要频繁结算，基础链上的哪个代价让人想到链下。按引言真实顺序，把作者从上一类方案转向下一类的理由嵌回译文旁。另写可以独立阅读的《前因后果》：普通场景怎样工作，只改变哪个条件，谁因此在第几步卡住或泄露了什么，本文改变了哪里，满足什么假设后付款才能继续？尽量让同一组人物和箭头回答这些问题。若专门要“只写问题”，图画到最后一个后果就收住。

> 结合模型、相关工作和实现，确定[通道、枢纽或网络]属于哪一类。逐一回答谁与谁开通道、维护几份独立状态、谁实际转发、谁只协调。把链类型、结算资产、手续费单位、原型和实测环境分开。跨链时顺着两条链上的两段状态说清如何关联、何时完成或退款。未指定底层链／币种的位置写明缺口。如给一种可能用法，注明是假定的部署情景及它需要的技术条件。

> 把相关工作浓缩为有区分度的对比表。行优先是引言及相关工作中的方案家族，列只取与本文动机直接相关的能力，写清“可以做到，但须满足什么条件”。把本文放在同样口径下。原表有更细结果时，就近嵌入并指出应读哪行哪列。

## 章内公式与算法

> 进入[章名]，分别列本章参数、独立原式和算法调用。用“算法名(原输入) → 输出”作为查阅入口。原文含有具体构造的多步算法，在当节按调用依赖重排，每个算法用独立的可读框，补齐材料支持的生成、判定、循环和返回。原文只提供外部接口时核到实参、用途和边界。交互型伪代码按角色整理。保留全文符号表，在最终 MD 的相关段落标出 🟥 **关键条件** 与 🟦 **本文改进**。

> 展开[验证算法]时，先逐项指出验证人实际收到或持有的数据来自哪里，定出本轮检查式。把生成端的表达式代回，写出中间等式、相消条件或谓词结果，以及失败或通过后的动作。只有原文接口时把本轮实参和核验边界写在对应位置。版面依[一行优先及成图核对](protocol-flow-diagrams.md#独立章的步骤标注与版式)。

### Markdown 中的重点长什么样

以下是按条件写的示例。实际精读时，换成本篇核实的条件和改进，分别贴在相关的验证式、机制或比较表旁。

> 🟥 **关键条件**　若本轮更新要求付款人和收款人分别签署自己的记录，缺少任一份授权，这笔付款就无法被采纳。

> 🟦 **本文改进**　若基线要求所有成员签署每次更新，而本文允许其余成员沿用旧授权，就应指出这笔付款少等了哪些成员，以及谁仍需签署什么。

两份 Markdown 都是可编辑的源稿。把方块和加粗标签直接写在实际段落中，数学维持原排版。关键条件也可以是决定结论的假设、验收门槛或失败后果。只有能指明相对基线改了哪一步时才标为“本文改进”。需要字体颜色时可对短语另加 HTML。仅支持基础 Markdown 的阅读器仍能显示两段的含义。每处高亮应回答一个具体问题，重复出现的术语维持常规字重。

## 画完整交易交互与算法推演

> 先核对作者的拓扑、成员和时序，选定一笔或一组贯穿的付款。从真实入口走到论文定义的终点。各阶段接回上一阶段的状态、签名、证明、金额和其他实际输出。已知数值来自本次原例，能算出的中间值逐步算出，其余沿用原文符号及约束。详见[交易实例的选取与核算](symbolic-walkthrough.md#交易实例的选取与核算)。

> 在《前因后果》设「完整交易交互」，用 Accio 图 2 的角色分栏，每个实际阶段一张黑白图，图首重列参与方和身份，步骤号跨图接续。三方及以上逐个写出所有实际参与方的生成、计算、签名、收发、转发、等待、验收和存档。未付款的成员也要列出其实际动作。有实际动作的 Operator、枢纽和合约各有明确归属。

> 按 BlindHub 完整版图 29 的细度，把「算法名（本次实参）→ 本次输出」、生成算式、逐项代入和结果放在执行方栏内。箭头标实际发送的字段，秘密留在持有者栏内。接收方逐项代入可取得的量，算到接受或失败。逐步核算旧余额、变化量和新余额。多人共用通式时仍列出各人的实际输入、判定和保存对象。材料只给接口时写出已知实参、输出条件和缺口。

> 每阶段写出各方实际采用的状态、保留的证据和下一步可使用的量。失败、超时或争议从实际触发处衔接，交代受影响的付款、失败后仍然可用的证据和资金去向。按原文保留并行和成员变化的生效点。

> 《全文精读》篇末的「完整交易算法推演」沿用同一组角色、实参和步骤号，逐行给出公式、伪代码与带载荷的消息传递。篇末可对应查看图中分段的长式。交互图要有本地计算和关键验算。版面过宽时按真实交互分段，首尾接回同一对象。适合用操作框的协议在框内写执行者、操作、结果及后继依赖。一般背景图按本篇原图选择图标、线型和配色。详见[分阶段交互图](protocol-flow-diagrams.md#分阶段交互图)。

## 手写算法与交互参考

算法介绍或推演的排法拿不准时，如本机技能目录下有 `library/手写算法与交互参考.md`，按其中索引选择对应页。章内算法介绍参考参数、调用式、分量计算、条件和输出的排列。验证参考目标式、代入、中间式和判定的相邻布局。交互参考角色栏、带参消息、本地计算与接收检查的位置。当前论文的符号、公式和协议事实按其原文及已取得的附录核对。

## 原图、实验和安全内容

> 每张原图、原表放到被解释的段落。先读原图，再写图下注解；关键参数流、验证条件或状态出口容易看错时，在文字解读旁放同源的标注图，用短箭头、方框点出一项必要条件、验证目标或状态出口。长理想功能或算法框按意义分段截，每块下解释触发、动作和输出，再衔接下一块。正文用合适栏宽，无损原图可放大。生成或标注后在最终大小检视下标、线宽、端点和图例。实验章节逐段完整翻译，直接放原图表，短释比较对象、坐标单位和实际趋势。

> 针对[安全主张]，保留对手可腐化谁、能看到什么、能拖延或拒绝哪个动作、哪些保证需要额外前提。环境和模拟器的额外说明用于理解这条证明。指出可从真实消息或公式核实的性质、仅由理想功能规定的检查、作者声称的结果及实质证据缺口，在摘要解读和结论里保留这些差别。

## 收尾和下次复用

> 原结论先译，再用自己的话写清最重要的问题和机制贡献。在《全文精读》将参考文献按期刊、会议及其他资料分开，按真实年份从新到旧，同年按核实的 CCF 等级，并附由同一书目生成的档次索引供从 A 到 C 查找。中文专业译题为主，保留英文原题及场所，A 类会议写明会名；系统或算法名称旁说明其含义。逐条过一遍本机所有已读论文，成稿只留下有证据可比的。提出“把甲的机制接入乙”时写明接口、原假设是否仍成立、会改变哪些状态、最小验证该怎么做。

> 交付两份成稿链接时，简短提醒读者审核成稿、候选代表原图和生成的交互图。标出原图号和挑选理由，新版本另列变化。明确批准后按 DOI 或题名更新同一条，保存获准材料并同步已配置的私有库。候选新画法可在本次交付中提示，待读者验证是否适合复用。

## 从实际成稿回查

拿出两份已经保存的 MD，实际打开对应段落做以下检查。某项对本篇适用却没有落点，就在那一段修好；确实没有该类材料时如实交代。局部任务只查所问范围。

| 读者操作 | 应当在成稿中看到什么 |
|---|---|
| 只打开精读的摘要、引言、任意技术章 | 摘要与引言有完整译文，解释和图贴在相应转折。技术章从自己的参数、公式与接口进入，不必到篇末找定义。 |
| 只打开《前因后果》 | 沿「完整交易交互」逐阶段读到结算，逐方找到本轮实际计算、收发、核验、存档和出口。上一图的输出是下一图可指认的输入。 |
| 对照《全文精读》篇末的「完整交易算法推演」 | 按与阶段图相同的步骤号、角色和输入逐行复算。已知金额能对上原例，余量沿原符号推到结果。 |
| 遮住算法解释，顺着关键图的一条箭头 | 发送人框内能查生成式，箭头能查实际载荷，收件人框内能查验收与结果；用发送人的本轮输出能解释接收人的检查。按原文能推而未印出的中间步骤实际写出来。 |
| 把浏览器或阅读器的颜色样式去掉 | 两份 MD 中的真正关键条件与机制改动仍能靠方块、粗体、文字标签识别。数学式仍可读。 |
| 读核心原图、理想功能或实验 | 关键图有同源的框箭标注和紧邻的短释；长理想功能按分支拆短；实验保留完整译文、原表原图及简短图解。 |
| 检查正文和《全文精读》篇末书目 | 两份正文用明确的作者或方案名，参考编号及 CCF 索引集中在《全文精读》。数学区间、索引和公式编号按原意保留。《前因后果》通过文档入口查书目。 |
| 在书目里查一篇早年的 A 会和一篇最新论文 | 从档次索引和年份主表都能定位相应条目，原编号、中英文题名、会刊、年份和等级齐备。已读库代表图能帮助下一次选择真实画法。 |
