# 原图对照与跨图流程

面向协议、交易、状态、算法及性能图。目标是让读者一边看论文原图，一边跟随同一组参数重放流程，知道当前图在做什么、每个关键对象对应哪一步，以及它怎样接到后续原图。保留正文图号，不另造一套图号替代原文定位。

## 1. 定位和盘点：先找到真实原图

- 盘点正文全部 Figure、Table 与相关附图，包含子图、跨页图、公式／伪代码图框。记录原图号、用途、实际 PDF 页、印刷页（不同才另列）、相关阶段及是否已目视核对。
- 正文中的“见 Fig. X”不等于原图所在页；图注页也可能与图体分离。查看对应页及必要的相邻页，确认图号、图注与图体匹配。不要把正文引用段落截图当作原图。
- 同一页可能有多幅图，一幅图也可能由多个位图、矢量对象和文本框组成。不能只抽取最大内嵌图片，也不能以位图数量或非文本对象数量判定“没有图”；支付通道论文的算法图常由纯文本与边框组成。
- 每张正文图表至少说明它回答的问题、所处阶段、主要内容与支持范围。核心图逐对象／箭头／子图展开；相关附图用于补齐关键依赖。未取得、不清晰或当前局部范围外的内容明确标注，不能计为已读。

可将索引合并进算法与阶段清单，避免反复输出重复表格：

| 原图／子图 | PDF 页与图体位置 | 回答的问题／类型 | 对应原文章节、阶段与算法原名 | 查看及讲解状态 |
|---|---|---|---|---|

## 2. 展示：保留可以核对的原图

- 默认将核心原图截图直接嵌入聊天与文档的对应阶段解释附近，并注明原文 Fig.、子图、页码和来源版本。图大时先展示完整图，再按阶段放大局部；关系清楚标注。纯算法／公式图框完整转排为展开的 LaTeX 文本后，不再贴同一算法的重复截图；含独立交互或架构信息的部分仍须展示和解释。
- 从 PDF 渲染或可靠原始图源提取，保留相关子图标记、箭头端点、图例、坐标、单位及图注。裁剪后目视核对；裁剪不可靠时展示已确认的完整原页，并标出本次讨论区域。
- 跨页图按同一原图的不同部分展示；同页多图分别定位。局部放大不能冒充完整图，不能把缺失图例、子图或边界条件的裁剪用于支撑完整结论。
- 原图保持原样。必要的标注版、教学重绘或协议时序另标“助手标注／重绘”，与原图并列；不通过生成式重绘改变原图内容。
- 图片与阅读文档只在本次授权范围保存，按当前环境要求使用可验证的图片嵌入方式；不能仅列图片文件链接。默认交付单份 `.md` 时，核对当前预览和下载后的图片可用性；采用内嵌图片前确认目标阅读器支持，不能仅凭 base64 已写入就声称可见。不支持时保留展开公式和文字解释，并据实说明图像显示缺口，不自动改交 PDF／压缩包。未获授权不公开上传论文图、阅读笔记或个人材料。
- 若当前界面确实不能显示图片，给出可打开的原页／图片链接、精确定位和文字对照，并明确显示限制；不能声称读者已看到原图。

## 论文式交互图的转排

先按 [支付协议的流程分类与成图](protocol-flow-diagrams.md) 核对论文类型、角色、支付情况和分支，再决定布局。本节适用于参与方分列的时序图及紧凑双栏／多栏协议框。时序图可按时间向下，紧凑协议框也可通过本地伪代码与跨列消息表达因果，不强制画生命线。两方、三方、四方等交互在可读时都可保留直接箭头，本地计算／验证放所属列，用阶段／动作名称定位，必要时保留章内局部序号；阶段分支图或架构组合图另选合适布局。先实际查看论文中对应的图与图注，借鉴角色分组、箭头组织和排版风格；参考图用于信息组织，不照搬其人数和结构。消息按 protocol-flow-diagrams.md 核对收发端和标签；清楚的跨列箭头与多接收广播保留，只在实际拥挤或歧义时避让、分区或摘要，不能默认卡片化。使用 LaTeX／TikZ 等精确排版后嵌入成图，不能把数学数组、纯清单或一般数据表当作主要交互。

- **列与生命线。** 参与方标题、所属计算列和有需要的生命线保持一致，各阶段保持角色顺序；紧凑协议框可以不画生命线。长公式只在所属列内换行，不能把其他列挤走。角色数量、身份与分组以论文为准，不从样图照搬中介或第三方。
- **箭头与字段。** 箭头端点落在对应生命线或明确的参与方列内消息位置，方向准确，不暗示未定义的角色；完整已知消息字段放在箭头上方或紧邻处，过长则分行并增加行距。多播、回传、自发本地计算分别表达，不能用居中箭头字符冒充跨列连接。
- **本地步骤与可读性。** 计算、检查、保存和状态更新对齐执行方列，不添加全局步骤索引；局部序号确有需要时置于左侧；白底、清晰数学字体、细线和足够留白，保持正常缩放可读。复杂阶段拆面板，不能靠缩成小字塞满一页。
- **先交付所需预览。** 用户明确要求先看图时，先完成一个有代表性的真实阶段并展示成图；只提供风格参考或要求更新技能不自动授权额外制图。已确认且适用的样式沿用；用户要求局部修图时只修相关处，避免无谓重做整份报告或多套试画。

- 在列首说明各方已有输入／状态，每条消息写已核实字段；将接收后的校验、abort 条件、保存与更新紧接在接收方列内。用短注释或图下逐行解释说明目的与依据，不把解释塞成不可读宽图。
- 先列真实主阶段数量和子阶段层级，按当前任务需要制作总览或局部图；已有总览能清楚表达的内容不再逐阶段重复制图，必要详图在对应章节附近出现。每步列实际算法调用、计算／校验式、消息完整已知字段、发送／接收方、前置条件和输出用途；图下解释本步符号、来源、为什么计算／发送及下游输入位置。不能仅贴整页 Create／Update 伪代码而不说明它分几阶段、怎样执行。
- 总览可在一图中组织多个阶段与分支，局部图聚焦需要展开的交互；仅在长协议实际不可读时拆成相互承接的面板，沿用阶段名称、算法原名和状态符号。原文允许并行时并列标出，未规定相对顺序时保持未知。
- 紧凑多方协议框即使含伪代码也属于交互图，保留并列参与方、跨方消息与 abort／return，不因“纯算法框不重复截图”而丢掉交互。单独的本地算法代码仍一算法一块，不能把这个规则用于拆散交互协议图。
- 完整算法另按 algorithms-playbook.md 重排为正常显示的公式，保持完整调用式、已定义输出、无展示序号的步骤与原符号，不附源码或重复生成算法截图；流程图仍须在相应角色或步骤写出实际算法调用、关键计算与校验，不因避免重复截图而只留空泛标签。交互面板是讲解层，保留原文定位，不把助手补充说成图上已有内容。
- 核验实际渲染、箭头方向、公式边界、横线等修饰、列归属和宽度；源码存在不等于已经渲染，显示失败时准确说明并保留可核对的替代布局。

### 成图可查看性验收

- 每张生成的交互图、流程图和交易图都必须实际编译／渲染，再打开成图目视检查；仅语法检查通过、进程退出成功或文件存在，均不足以证明图可查看。正常显示的算法公式仅在出现实际显示问题时定向检查，不为满足成图验收另生成算法截图、重复源码或测试网页。
- 逐图核对原文符号、中文与数学字体、箭头端点、参与方列、上下标、公式边界、裁切、重叠和正常缩放下的可读性；发现缺字、乱码、渲染错误或内容截断时先修复再交付。不得为绕过渲染问题改写原文符号。
- 用户报告乱码或显示失败时，定位其看到的公式或图像，分别检查解码、LaTeX 语法、字体和目标阅读器支持；能访问目标界面就实际重现，不能访问则说明未核验并给出可查看的局部预览。无替代字符、编译成功或 base64 有效均不能证明目标界面显示正确。
- 在聊天正文和 Markdown 对应段落实际嵌入可渲染成图，并紧邻提供图的解释；仅有文件链接、图片路径或文档中存在图片不算聊天交付。内联布局不可靠时用已打开检查的 PNG 截图嵌入，不自动交付 PDF 或压缩包。LaTeX／TikZ 等源码仅在用户明确要求时附上供复现，不能代替可查看成图；纯文字表格可辅助理解，不能声称替代图已完成。
- Markdown 等文档引用生成图时，核对最终交付路径、图片嵌入和链接；迁移后仍需连同资源可打开，不能依赖仅在生成环境存在的临时路径。无法完成渲染或查看验证时据实说明失败项，保留可核对内容，不宣称图片已可查看。

## 3. 每张核心图的讲解顺序

以下适用于论文精读中的图文讲解；用户单独要成图时按 protocol-flow-diagrams.md 直接给图，必要角色、阶段、算法与条件留在图中，不强行另附长说明。论文讲解中的图至少解释“为什么放这张图、描述什么过程／关系、在论文哪个位置起什么作用”；包括安全证明示意图和辅助图，不能只有图或图注。下列逐对象、公式和状态的深入讲解用于核心图；非核心安全图可简述目的、对象、主要过程及支持的结论，不机械扩写证明。

### 本阶段为什么需要这张图

先用自然语言说明它解决哪一个子问题、输入从哪里来、现在要得到什么；说明它是协议定义、流程示意、算法构造还是实验结果。图注可以辅助解释，但不能代替实际图像阅读。

### 对照图例与对象

解释影响含义的参与方列、通道实例、链／合约、框、颜色、实线／虚线、箭头、括号、上／下标及子图标签。颜色或位置没有图例时保留未知，不按惯例猜；方括号可能表示模板或条件状态，必须依本文定义判断。

必要时使用窄表：

| 原图中的标签／箭头 | 具体对象与执行方 | 对应原文章节／动作／算法／公式 | 前后变化与读者应关注的条件 |
|---|---|---|---|

不同论文的同名标签分别解释。区分环列表与适配语句、金额承诺与环内承诺、签名与证书、通道状态与链上交易，不因图上简称相近就合并。

### 沿同一执行走过图中的关键部分

按因果依赖而非凭页面排版排序。先解释输入和本地构造，再解释消息传递、接收校验、输出保存与状态生效。把每个关键箭头或图块映射到原文章节中的具体动作、算法原名及原文公式；在需要处嵌入 [参数化演算](symbolic-walkthrough.md)。

覆盖各子图及影响正确性、资金、秘密、性能结论的内容；机械重复的箭头可成组说明，但须说明各角色／轮次映射。局部问题只展开所问部分与必要依赖，保持范围清楚。

图上未画出的校验或子程序，只有正文、伪代码或附录支持时才补讲，并标注来源。图、图注与正文冲突时并列定位；不静默重排箭头来修正论文。

### 说明此时得到什么，再接下一张原图

收束本阶段：谁现在持有什么、何种状态已确认、还有什么不能做。指出后续具体原图／子图及输入来源，例如“本图生成的预签名成为后续更新图中的验证输入”。

给出两图之间的对象映射：角色别名、同一通道还是另一通道、消息封装、会话与轮次、候选与确认状态。若接口缺少字段，写出具体缺口；不能靠同名参数假定已经传输。

多图按依赖组成阅读路线。全景图可先于更早编号的原语图讲解，但应明示“先看全景，再展开其中子程序”，不强制按图号线性阅读，也不把两张重复示意图计成两次执行。

## 机制逐步引入与交易分支

- 对逐步完善方案的系列图，按“上一版已保证什么 → 剩余攻击／缺口 → 新机制约束哪个对象 → 加入后的保证 → 去掉后会怎样”串成因果链。用户只要串讲时直接给连贯叙述，不重复堆砌算法细节。
- 核对“上述问题／前述攻击”等指代的紧邻原文。PPT 跳过中间图或段落时，指出省略了哪一层问题；不能把完全拒付、少付多取、关系关联与恶意锁资混成同一种攻击。
- 对每条转发箭头说明接收方为何需要该对象、此前是否已经掌握、拿到后执行哪一步；转发承诺不是收款收据。区分论文选择的消息安排与唯一必要安排；讨论替代发送路径或相反付款顺序时，逐角色分析风险与隐私影响，不冒充原文流程。
- 对交易图先区分资金交易、承诺交易、分割交易及条件款交付／退款等实际层次。逐分支说明花费哪个输出、覆盖全部通道资金还是某笔条件金额、授权者、等待起点、时间锁及输出未花费条件；同一输出的互斥花费不能理解为依次执行或重复支付。
- 解释未响应退出时，先说明谁保存完整交易正文、谁只参与盲签／持有摘要或承诺、为什么不能独立构造退出，再串联触发、等待、响应与逾期路径。时间到达只使交易可执行，不等于自动广播或自动转账；按原文分别分析旧状态作弊与未响应。
- 图中数字上标、同字母角色与时间参数等先核验含义，不按外观认定为状态编号。简化示例不能让盲方突然知道隐藏金额；需要数值直觉时明确观察者视角，并保留完整的符号说明。

## 4. 不同类型图的专项问题

| 图的类型 | 重点对照 |
|---|---|
| 系统／架构图 | 参与方、信任边界、链上／链下、资金与信息各自的入口出口；方框是否为真实角色还是抽象接口 |
| 协议／时序图 | 箭头方向、发送与接收、执行者、本地顺序、等待条件、跨通道依赖；横轴／纵轴是否确实表示时间 |
| 交易依赖图 | 输入输出与父交易引用、签名者、脚本／时间锁、正常与惩罚分支；依赖箭头不自动代表已广播或确认 |
| 状态机／余额图 | 候选、条件、接受与最终状态，转移触发条件、旧状态处理、余额／锁定／费用口径 |
| 算法／公式图框 | 提取算法名、输入输出、随机数、循环和失败分支，纳入完整算法清单；从构造代入验证式 |
| 共识／流水线图 | 节点、epoch、批次、投票层与证书、阈值、允许重叠的阶段；消息数与轮数分别计量 |
| 性能／实验图 | 坐标、单位、尺度、图例、基线、工作负载、硬件、误差与测量对象；计算成本、网络延迟、链上确认分开 |
| 对比表／结果表 | 每个符号的图例、比较前提、注脚、哪些是作者归类及哪些已核对；不将勾选当作独立证明 |

性能章节及图表文字按 reading-framework.md 完整翻译并排版，保留作者对测量、对照、趋势和结论的说明；不主动估读曲线、计算提升或扩展评价。用户另要求分析时再做，估读明确标注，不补造精确数值、显著性或配置。

## 5. 覆盖与交付核对

- 原图索引与正文、附录交叉核对；已识别不等于已目视查看，已查看不等于已讲解。状态与材料缺口据实报告。
- 每张核心图的解释覆盖问题、原图、图例、关键对象／子图、流程与公式对应、输出能力和后续连接。
- 图中箭头分别识别为消息、资金／交易依赖、状态转移或示意关联；必要时明确“原文未规定相对顺序”。
- 图片完整清晰、路径存在；最终文档展示顺序与解释相邻。原图不可读取时说明影响，不用正文猜补图。
- 算法清单、阶段地图和原图索引相互对应，正文全部图表及关键附图都有交代。保持流程叙述可读，不按固定字数、行数、图数或固定数量质疑凑篇幅。
