# 基于阅读反馈优化

在用户要求“更新／优化论文精读 skill”“以后都这样读”，或明确提出可复用偏好时读取。用户希望在多个对话中逐步完善同一个技能；持久依据是 [跨设备使用](distribution.md) 指定的统一仓库，而非某个对话开始时加载的旧副本。

## 区分一次性追问与长期规则

本篇纠错或“把这一步再解释一下”只修改当前讲解，不自动更新技能。明确的“以后每篇都”“更新 skill”“把本次需要长期保留的要求合并进去”授权保存可复用规则；可以逐条提出，也可以在读完一篇后批量总结。

依据当前可见对话归纳，不能假装已读过其他未提供的对话。已写入仓库的反馈从最新版继承。若长期偏好相互矛盾且无法兼容，指出具体冲突并只澄清这个取舍；一般纠错、去重和合并不需反复确认。

## 跨对话更新流程

1. **先读最新版。** 读取 distribution.md 中的仓库地址、分支和目录，取得当前分支头、远端 SKILL.md 的 metadata.version，以及修改所涉及的完整参考文件。比较当前设备副本和远端内容；不能因为本地版本号相同就跳过差异检查。未能读取远端时只能做本地待合并修订，不能声称已基于最新版本更新。
2. **提炼反馈。** 定位具体失误，转换成窄而可复用的要求，避免把某篇论文机制变成通用假设。只提炼规则，不自动把整段聊天、论文原文或个案材料复制进公开仓库。保留有用的既有要求，合并同义表述，不不断追加重复的“必须”。
3. **合并而非覆盖。** 以远端最新版为基础，整合本次反馈与当前设备尚未同步的有效改动。通用正确性约束放 SKILL.md，全文讲解细节放 reading-framework.md，更新和分发流程放对应参考文件。不得用对话开头的旧整份文件覆盖其他对话的新规则，也不修改其他技能或账户设置。
4. **版本与验证。** 从远端最新 metadata.version 递增：纠错用补丁、增加能力用次版本、默认行为大改用主版本。运行可用的技能结构校验，检查引用与界面说明，并用触发反馈的小案例检查修改是否解决问题；改时序规则时再检查允许并发或含失败分支的案例，防止捏造依赖。需要时一并修正当前讲解。
5. **提交并处理竞争更新。** 在用户已授权的范围内，基于读取的分支头提交，使用非强制推送或带预期分支头的非强制更新。若另一个对话先提交，重新取得最新版，合并本次改动，重算版本并复核后再提交；最多重试两次。仍有竞争、内容冲突或权限问题时保留待同步改动并报告，不强制覆盖，不无限重试。
6. **核实并同步。** 成功后回读远端文件和版本，再同步当前设备的实际个人技能安装目录，以及本任务确实维护的可下载副本。别只改一个输出目录的旧文件。若远端或本地任一保存失败，分别报告实际成功部分和待完成部分。
7. **报告结果。** 简述新增、修改或合并了哪些规则、新版本、验证结果及提交位置。明确哪些副本已更新；其他电脑仍需同步，其他正在进行的对话也需重新加载新版，不能把本机保存或一次推送说成所有设备与对话都已生效。

尚未配置共享来源时，交付版本化更新包并说明待同步；没有可用写入能力时，不以“已经记住”代替实际文件保存和仓库同步。

## 用户可直接使用的指令

> 更新论文精读 skill：请把本次对话中已经明确、需要长期保留的阅读要求合并到仓库最新版，保留其他对话已有的规则，更新版本并同步 GitHub 和当前设备。完成后说明改了什么及同步是否成功。

用户也可在指令后补充“刚才的问题是……；以后统一要求……”。这些要求需要从实际反馈提炼；示例措辞本身不是已经选择的阅读偏好。

读完一篇论文可以提出一两条有依据的优化建议；未经用户要求或已有持久偏好授权，不自动写入技能。未保存到统一来源的聊天反馈不自动跨对话累积。
